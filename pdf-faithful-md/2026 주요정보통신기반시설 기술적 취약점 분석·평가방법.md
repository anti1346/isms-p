## 1. 문서 개요

이 문서는 주요정보통신기반시설의 기술적 취약점 분석·평가를 수행할 때 참고할 수 있는 항목별 점검 가이드입니다. 각 항목은 점검 내용, 목적, 보안 위험, 판단 기준, 조치 방법을 중심으로 정리되며, 운영 환경에 따라 세부 기준의 해석은 달라질 수 있습니다.

핵심 원칙은 다음과 같습니다.

- 점검 방법은 일반적인 기준을 제시하는 참고 자료이며 절대적인 기준은 아닙니다.
- 실제 점검 결과는 운영 환경, 정책, 패치 상태, 위험도를 종합해 최종 판단해야 합니다.
- 취약점이 발견된 경우, 단순히 결과만 적는 것이 아니라 원인과 조치 방안을 함께 정리해야 합니다.

## 4. 핵심 점검 포인트

### 4.1 계정 보안

- root 계정은 원격 접속을 제한한다.
- 불필요한 계정, 중복 UID, 잘못된 GID를 제거한다.
- 비밀번호 정책을 설정하고 잠금 임계값을 적용한다.
- 관리자 그룹 구성원을 최소화한다.

### 4.2 파일 및 디렉터리 보안

- 민감 파일의 소유자와 권한을 제한한다.
- 시스템 시작 스크립트, 패스 설정, 환경변수 파일을 보호한다.
- SUID, SGID, Sticky bit 설정을 점검한다.
- world writable 파일과 숨겨진 파일을 정기적으로 점검한다.

### 4.3 네트워크 및 서비스 보안

- 불필요한 서비스와 익명 접근 서비스를 비활성화한다.
- Telnet, FTP, r 계열 서비스, NFS, SNMP 등 취약한 서비스는 점검 및 차단한다.
- 패치 적용 여부와 보안 버전 기준을 확인한다.
- 로그 수집과 시각 동기화 정책을 유지한다.

## 5. 대표 항목별 정리

### U-01 root 계정 원격 접속 제한

- 점검 목적: 관리자 권한 탈취를 방지한다.
- 보안 위험: root 계정에 대한 원격 접근 허용 시 시스템 장악 위험이 높다.
- 권장 조치: SSH에서 `PermitRootLogin no` 적용, sudo 또는 별도 관리자 계정 사용.

### U-02 비밀번호 관리정책 설정

- 점검 목적: 약한 비밀번호 사용을 방지한다.
- 보안 위험: 취약한 비밀번호는 무차별 대입 및 사전 대입 공격에 취약하다.
- 권장 조치: 최소 길이, 복잡도, 만료 정책, 비밀번호 기억 정책을 적용한다.

### U-12 세션 종료 시간 설정

- 점검 목적: 장시간 미사용 세션을 자동 종료한다.
- 보안 위험: 유휴 상태인 세션은 비인가 접근 경로가 될 수 있다.
- 권장 조치: `TMOUT=600` 또는 `autologout=10` 설정.

### U-13 안전한 비밀번호 암호화 알고리즘 사용

- 점검 목적: 비밀번호 노출 시 복호화 공격에 대비한다.
- 보안 위험: 취약한 해시 알고리즘은 쉽게 역추적될 수 있다.
- 권장 조치: `SHA-256`, `SHA-512`, `yescrypt` 등 안전한 알고리즘 사용.

## 6. 상세 점검 체크리스트

실무에서는 항목별 문장 요약보다 실제 확인 절차와 위험 요소를 함께 적는 것이 중요합니다. 아래는 운영 중 점검 시 바로 적용할 수 있는 상세 체크리스트입니다.

### 6.1 계정 관리 상세 점검

#### 1) root 계정 원격 접속 제한

- 확인 항목
  - SSH 포트에서 root 직접 로그인 허용 여부 확인
  - `sshd_config`의 `PermitRootLogin` 값 확인
  - 관리자 권한을 별도 계정 또는 `sudo`로 제한하는 정책 적용 여부 확인
- 위험 요소
  - root 계정이 원격으로 열리면 비인가 접근 시 즉시 시스템 장악 가능
- 점검 명령 예시
  - `grep -E 'PermitRootLogin|AllowUsers|DenyUsers' /etc/ssh/sshd_config`
- 권장 조치
  - `PermitRootLogin no` 적용
  - 관리자 계정과 운영 계정을 분리

#### 2) 비밀번호 관리정책 설정

- 확인 항목
  - 최소 길이, 대문자/소문자/숫자/특수문자 조합, 비밀번호 변경 주기, 만료 기간
  - 이전 비밀번호 기억 개수
- 위험 요소
  - 약한 비밀번호는 무차별 대입 공격에 취약하고, 계정 도용으로 이어질 수 있음
- 점검 명령 예시
  - `grep -E 'PASS_MAX_DAYS|PASS_MIN_DAYS|PASS_WARN_AGE|PASS_MIN_LEN' /etc/login.defs`
  - `grep -E 'minlen|dcredit|ucredit|lcredit|ocredit' /etc/security/pwquality.conf`
- 권장 조치
  - 최소 8자 이상, 영문/숫자/특수문자 조합, 90일 내 만료 정책 적용

#### 3) 계정 잠금 임계값 설정

- 확인 항목
  - 로그인 실패 횟수
  - 잠금 유지 시간
  - 관리자 예외 처리 여부
- 위험 요소
  - 로그인이 무제한 허용되면 공격자가 비밀번호를 반복적으로 시도할 수 있음
- 점검 명령 예시
  - `grep -E 'pam_tally2|faillog|auth.*fail' /etc/pam.d/system-auth /etc/pam.d/password-auth`
- 권장 조치
  - 실패 5회 이상 시 잠금, 일정 시간 이후 자동 복구

#### 4) UID/GID 관리

- 확인 항목
  - root 외의 UID 0 사용 여부
  - 계정과 그룹 매핑의 일관성
  - 중복 UID 또는 삭제된 GID 사용 여부
- 위험 요소
  - UID/GID 충돌은 권한 오인식, 잘못된 파일 접근, 관리자 권한 유출로 이어질 수 있음
- 점검 명령 예시
  - `awk -F: '$3 == 0 {print $1, $3}' /etc/passwd`
  - `awk -F: '{print $3}' /etc/passwd | sort | uniq -d`
  - `awk -F: '{print $1,$3}' /etc/passwd; getent group`

### 6.2 파일 및 디렉터리 관리 상세 점검

#### 1) 민감 파일 권한 점검

- 확인 항목
  - `/etc/shadow`, `/etc/passwd`, `/etc/hosts`, `/etc/inetd.conf`, `/etc/syslog.conf`의 소유자 및 권한
- 위험 요소
  - 일반 사용자에게 쓰기 권한이 부여되면 파일 변조 및 정보 유출 가능
- 점검 명령 예시
  - `ls -l /etc/passwd /etc/shadow`
  - `stat -c '%A %U %G %n' /etc/passwd /etc/shadow`
- 권장 조치
  - root 소유권 유지, 최소 권한으로 제한 (`chmod 400`, `chmod 640` 등)

#### 2) SUID/SGID/Sticky bit 점검

- 확인 항목
  - 불필요한 SUID 프로그램 존재 여부
  - `world writable` 파일 존재 여부
  - 임의의 파일이 특정 사용자에 의해 수정될 수 있는지 여부
- 위험 요소
  - 불필요한 SUID는 권한 상승의 경로가 될 수 있음
- 점검 명령 예시
  - `find / -perm -4000 -o -perm -2000 2>/dev/null`
  - `find / -type f -perm -0002 2>/dev/null`
- 권장 조치
  - 불필요한 SUID 제거, 쓰기 권한 최소화

#### 3) 홈 디렉터리와 환경 변수 파일 관리

- 확인 항목
  - 사용자 홈 디렉터리 소유권
  - `.rhosts`, `hosts.equiv` 파일 사용 여부
  - 환경 변수 파일의 소유자/권한
- 위험 요소
  - 홈 디렉터리에 민감 설정이 남아 있으면 신뢰 경계가 약해짐
- 권장 조치
  - 불필요한 접속 파일 제거
  - 사용자별 환경 파일 접근 권한 제한

### 6.3 서비스 관리 상세 점검

#### 1) 불필요한 서비스 비활성화

- 확인 항목
  - `telnet`, `ftp`, `rlogin`, `rsh`, `talk`, `finger`, `NFS`, `SNMP`, `automountd` 등 비활성화 여부
- 위험 요소
  - 사용하지 않는 서비스는 공격 표면을 크게 증가시킴
- 점검 명령 예시
  - `service --status-all`
  - `systemctl list-unit-files --type=service`
- 권장 조치
  - 불필요한 서비스 제거 또는 `disable` 처리

#### 2) 네트워크 접근 제어

- 확인 항목
  - 허용된 IP/포트, firewall 규칙, 접근 제어 정책
  - DNS zone transfer 허용 여부
  - SNMP community 문자열 설정
- 위험 요소
  - 허용 범위가 넓으면 내부 서비스가 외부로 노출될 수 있음
- 점검 명령 예시
  - `iptables -L`
  - `firewall-cmd --list-all`
  - `netstat -tulpn`
- 권장 조치
  - 필요한 서비스만 외부 접근 허용, 불필요한 포트 차단

### 6.4 패치 및 로그 관리 상세 점검

#### 1) 보안 패치 적용

- 확인 항목
  - 운영 체제 보안 패치 적용 주기
  - 취약점 보고서와 CIS, 벤더 권고사항 반영 여부
- 위험 요소
  - 패치가 누락되면 이미 공개된 취약점이 그대로 남아 있음
- 권장 조치
  - 정기적인 보안 패치 스케줄 운영

#### 2) 로그 관리와 시각 동기화

- 확인 항목
  - 로그 저장 위치, 권한, 보관 기간
  - NTP 동기화 상태
  - 중요한 이벤트(로그인, 파일 수정, 권한 변경) 기록 여부
- 위험 요소
  - 로그가 누락되면 보안 사고 추적이 불가능함
- 점검 명령 예시
  - `journalctl -xe`
  - `timedatectl status`
  - `ls -ld /var/log`

## 7. 점검 기준 및 실무 예시

### 7.1 양호/취약 판단 기준 예시

- 양호
  - 원격 접근 시 root 로그인이 차단됨
  - 비밀번호 정책이 명시적으로 설정되고 적용되고 있음
  - 임계값을 초과한 로그인 실패에 대해 자동 잠금이 동작함
  - 민감 파일의 소유자가 root이며, 권한이 최소치로 제한됨
- 취약
  - root 계정이 SSH 접속에 허용됨
  - 비밀번호 정책이 없음
  - 로그인 실패 제한이 없음
  - 시스템 파일이 일반 사용자에게 쓰기 가능 상태임

### 7.2 실제 점검용 명령 예시

```bash
# SSH root 접속 제한 확인
grep -E 'PermitRootLogin|AllowUsers|DenyUsers' /etc/ssh/sshd_config

# 비밀번호 정책 확인
grep -E 'PASS_MAX_DAYS|PASS_MIN_DAYS|PASS_WARN_AGE|PASS_MIN_LEN' /etc/login.defs

# UID 0 계정 확인
awk -F: '$3 == 0 {print $1, $3}' /etc/passwd

# 중복 UID 확인
awk -F: '{print $3}' /etc/passwd | sort | uniq -d

# 파일 권한 확인
ls -l /etc/passwd /etc/shadow

# 세션 타임아웃 확인
grep -E 'TMOUT|autologout' /etc/profile /etc/csh.cshrc /etc/csh.login 2>/dev/null
```

### 7.3 보고서 작성 예시

> 점검 결과: root 계정의 원격 접속 제한이 적용되지 않아 SSH 접속 시 관리자 권한을 직접 사용할 수 있는 상태였습니다. `/etc/ssh/sshd_config`에서 `PermitRootLogin yes`가 확인되었고, 비밀번호 정책 및 계정 잠금 임계값도 미설정 상태였습니다. 따라서 관리자 권한 탈취 위험이 높다고 판단되며, `PermitRootLogin no` 적용, 비밀번호 정책 강제, 로그인 실패 기반 잠금 설정을 우선 반영해야 합니다.
